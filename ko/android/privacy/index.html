1. 적용 범위와 책임 주체

DoseWeek 앱과 이 개인정보처리방침은 대한민국에 있는 개인 개발자 Wonyoung Choi가 운영해요. 개인정보 처리에 관한 문의는 wonyoung@wonyoungchoi.dev로 보내 주세요.

DoseWeek Android는 18세 이상만 쓸 수 있어요. 생년월일이나 숫자로 된 나이는 입력받지도, 전송하지도 않아요. 버전별 이용 자격 선택만 기기에 저장해요. 거절하거나 확인하지 않으면 일반 앱 기능과 AI를 쓸 수 없어요. 이때도 기존 로컬 기록은 삭제하지 않아요. 앱 잠금을 설정했다면 인증한 뒤 암호화 백업 파일과 복구 코드를 내보내는 기능만 쓸 수 있어요. 사용 분석, 국외 이전, AI 기능 동의는 각각 따로 받아요.

Google Play는 앱을 배포하고, Android는 설치, 앱 전용 저장소, 백업 제어, 삭제 같은 플랫폼 기능을 제공해요. Google Play, Android, 사용자가 고른 문서 제공자가 따로 처리하는 부분에는 각 제공자의 약관과 정책이 적용돼요. 이 방침은 DoseWeek 앱 안의 처리만 설명해요. 앱은 건강 기록을 개발자나 Google Play로 보내지 않아요. 선택 연동을 켜지 않는 한 기록은 기기에 머물러요. 각 연동이 하는 일은 3항과 4항에서 설명해요.

2. 사용자가 기기에 저장하는 정보

DoseWeek는 사용자가 직접 입력하고 확인한 다음 정보를 앱 전용 저장소에 보관해요. 이 방침에서 설명하는 선택 연동, 백업, 내보내기를 빼면, 이 정보는 앱 기능을 제공하려고 Android 기기 안에서만 처리해요.

  • 제품·지역 항목, 용량, 요일, 시간과 시간대 기준을 포함한 주 1회 주사 일정
  • 날짜, 시간, 용량, 선택한 주사 부위와 선택 메모를 포함한 실제 투여 기록
  • 사용자가 건너뜀으로 표시한 주간 일정
  • 남은 투여 횟수로 관리하는 재고 수량
  • 사용자가 직접 입력한 체중과 허리둘레
  • 컨디션 기록(증상, 심각도, 시각, 선택 메모)과, 사용자가 입력한 사유를 포함한 투여 기록의 수정·삭제 변경 이력
  • 사용자가 고른 설정: 액센트 색상과 화면 모드, 알림 문구에 약 이름을 표시할지 여부를 포함한 알림 옵션, 앱 잠금 사용 여부

3. 선택 서비스와 사용 분석

DoseWeek 1.0.5는 기본 상태에서 아래 기능이나 자동 처리를 쓰지 않아요. 모든 기록은 사용자가 직접 입력하고 확인해요.

  • 개발자 서버로의 건강 기록 수집·전송 또는 다른 회사나 사용자에게 자동 공유
  • DoseWeek 계정, 개발자 운영 클라우드 또는 자동 동기화
  • 오류 보고 SDK
  • 선택적 동의 없이 Firebase 사용 분석 시작
  • 생성형 AI
  • Health Connect 쓰기 또는 삭제 권한
  • 워치 앱 또는 서버에서 보내는 푸시 알림

일정, 투여 기록, 메모, 신체 측정값 같은 건강 기록은 기본적으로 기기에 저장돼요. 개발자는 이 기록을 받지 않아요. 내보내기, 백업, 선택 연동은 따로 설명해요. 선택 사용 분석에는 아래 규칙이 적용돼요.

필수 개인정보 고지를 확인했다고 분석을 허용한 것은 아니에요. 사용 분석과 국외 이전에 각각 따로 동의한 경우에만 분석을 켜요. 두 선택 동의는 기본적으로 꺼져 있어요. 하나라도 거절하거나 철회하면 분석을 꺼요.

사용 분석은 선택 사항이고 처음에는 꺼져 있어요. 필수 개인정보 고지를 확인해도 분석에 동의한 것은 아니에요. 따로 허용한 뒤에만 Google Analytics for Firebase가 시작돼요. 그러면 최초 실행, 세션, 사용 빈도, 사용 시간, 앱·운영체제 업데이트 같은 자동 수명 주기·기술 이벤트를 Google에 보내요. 개발자는 사용 현황을 파악하려고 보고서를 봐요. DoseWeek는 맞춤 이벤트를 추가하지 않아요.

분석에는 Firebase가 만든 앱 인스턴스·설치 식별자, 이벤트 시각, 앱 버전, 언어, 기기 브랜드·모델·유형, 마이너 버전을 포함한 운영체제 정보, 화면 해상도가 들어갈 수 있어요. Google은 서비스 운영과 도시 같은 대략적인 위치 산출을 위해 IP 주소를 처리해요. 도시에서 도출한 좌표는 사용자의 GPS 위치가 아니에요. 분석에는 GPS나 위치 권한을 쓰지 않아요. Google은 해외에 있을 수 있는 자사 서버에서 처리하고, 개발자는 보고서를 볼 수 있어요. 이 기록 자체가 익명 정보인 것은 아니에요.

DoseWeek는 건강 기록, 약물명, 용량, 메모, 입력한 글·음성, 화면 이름이나 경로를 분석에 보내지 않아요. 사용자 ID나 맞춤 사용자 속성도 설정하지 않아요. 광고 ID·Android ID (SSAID) 수집, 자동 화면 보고, Google 신호, 광고 개인화는 꺼져 있어요. Crashlytics와 Performance Monitoring은 쓰지 않아요.

Google Analytics의 사용자·이벤트 수준 보존 기간은 2개월이에요. 새 활동이 있어도 기간을 다시 시작하지 않아요. 설정 변경은 24시간 뒤에 적용돼요. 만료된 데이터는 정확히 2개월이 되는 순간이 아니라 Google의 월별 절차에서 삭제돼요. 이 설정은 표준 집계 보고서에는 적용되지 않고, 보고서를 영구히 제공한다는 보장도 아니에요.

익명 월별 합계는 식별 가능성을 없애는 개인정보 검토와 검증된 내보내기를 거친 뒤에만 오래 보관할 계획이에요. 아직 실제 데이터로 이런 내보내기를 한 적은 없어요. 원시 분석 데이터는 익명으로 취급하지 않아요.

사용 분석 동의는 선택 식품 라벨 인식, 그리고 따로 알린 Google ML Kit 측정 정보에 대한 동의와 달라요. 한쪽 선택을 바꿔도 다른 쪽은 바뀌지 않아요.

Health Connect 연동은 읽기 전용이에요. DoseWeek는 사용자가 공유한 체중, 키, 체지방률, 제지방량을 읽기만 해요. 쓰기나 삭제 권한은 요청하지 않아서 다른 앱이 가진 기록을 바꿀 수 없어요. 읽은 정보는 앱 전용 저장소에 보관하고 개발자에게 보내지 않아요.

Google Drive 연동을 켜면 앱이 암호화된 백업을 사용자 본인의 Drive 앱 데이터 폴더에 올릴 수 있어요. 개발자는 사본도 키도 갖지 않아요. Drive가 볼 수 있는 정보와 복구 코드 처리는 4항에서 설명해요.

캘린더 연동을 켜면 DoseWeek는 사용자가 고른 캘린더 하나에 다가오는 주사 예정일마다 30분짜리 일정을 기록해요. 일정에는 제목과 시간만 담아요. 제목은 기본값이 “개인 알림”이고, 설명형 제목을 직접 고른 경우에만 “주사 예정일”이 돼요. 약 이름, 용량, 주사 부위, 메모는 절대 기록하지 않아요. 앱은 캘린더 목록과 자신이 표시해 둔 일정만 읽고, 그 일정만 수정·삭제해요. 캘린더가 Google이나 삼성 같은 계정에 속하면 그 제공자가 자체 개인정보 처리방침에 따라 일정을 저장·동기화해요. 캘린더를 공유한 사람에게도 일정이 보일 수 있어요. 개발자는 아무것도 받지 않아요. 연동을 끄면 다가오는 일정을 삭제할 수 있어요. 앱을 삭제한 뒤 캘린더에 남은 일정은 그대로 남아요.

4. 저장 위치, 백업과 기기 이전

현재 기록은 모두 Android 앱 전용 저장소에 로컬로 보관돼요. Android 시스템의 클라우드 백업과 기기 간 전송 대상에서는 빠져 있어요. 사용자는 Android 시스템 파일 선택기(SAF)로 위치를 정해 모든 앱 데이터를 암호화된 백업 파일로 직접 저장하고, 그 파일을 골라 복원할 수 있어요. 이 과정에는 DoseWeek 계정이나 넓은 저장소 권한이 필요 없고, 네트워크도 쓰지 않아요. 백업은 Android용 DoseWeek에서만 복원할 수 있어요. 다른 플랫폼의 DoseWeek는 백업 형식이 달라서 플랫폼 사이에서 백업을 옮길 수 없어요.

외부나 클라우드 문서 제공자를 고르면 그 제공자가 자체 개인정보처리방침과 약관에 따라 백업 파일을 저장해요. DoseWeek 개발자는 백업 파일이나 복구 코드를 받지 않아요.

백업 파일은 AES-256-GCM 인증 암호화와 별도의 고엔트로피 복구 코드로 보호돼요. 이 파일 백업은 사용자가 직접 만들어요. 자동으로 실행되는 백업은 아래에서 설명하는 선택 사항인 Google Drive 백업뿐이고, 이 백업은 기본적으로 꺼져 있어요. DoseWeek가 운영하는 클라우드 백업이 아니며, 코드 재설정 서비스도 없어요. 파일과 코드는 따로, 안전하게 보관하세요. 코드를 잃으면 개발자나 지원 담당자도 코드를 재설정하거나 파일을 복호화할 수 없어요. 파일 백업의 복구 코드를 보관했다고 확인하기 전까지, DoseWeek는 그 코드를 다시 볼 수 있도록 기기가 보관하는 키로 감싸 이 기기에만 보관해요. 확인하면 이 사본을 삭제해요.

복원할 때 DoseWeek는 파일 전체를 복호화하고 구조와 데이터 관계를 끝까지 검증해요. 검증을 마친 뒤에만 현재 앱 데이터를 하나의 로컬 트랜잭션으로 원자적으로 교체해요.

선택 사항으로, DoseWeek는 이 암호화된 백업을 사용자 본인의 Google Drive 앱 데이터 폴더에 보관할 수도 있어요. Drive가 볼 수 있는 것은 임의 식별자가 들어간 파일 이름, 파일 크기, 생성 시각, 페이로드 버전, 키 버전, 무작위 스냅샷 식별자뿐이에요. 약 이름, 용량, 측정값, 치료 날짜, 메모는 암호화된 봉투 밖에 드러나지 않아요.

암호화는 업로드 전에 기기에서 이뤄지고, 오프라인 파일 내보내기와 같은 AES-256-GCM 봉투를 써요. 복구 코드는 백업과 함께 저장하지 않고 어디에도 보내지 않아요. 보관했다고 확인하기 전까지는 같은 코드를 다시 볼 수 있고, 확인한 뒤에는 다시 보여 주지 않아요. 자동 백업을 시작하려면 그 코드를 다시 입력해야 해요. 코드를 잃으면 개발자도 백업을 읽거나 복구할 수 없어요.

선택 사항인 자동 백업은 기본적으로 꺼져 있어요. 켜면 기기 상태가 허용할 때 하루에 한 번쯤 실행되고, 정확한 시각은 약속하지 않아요. Drive에서 백업을 삭제하면 되돌릴 수 없어요. Drive는 앱 데이터 파일에 휴지통을 제공하지 않기 때문이에요. 연결을 해제하면 이후 업로드는 멈춰요. 하지만 이미 Drive에 있는 백업이나 기기의 기록은 삭제되지 않아요. 이 기기에 저장된 복구 코드 사본을 지우는 것은 따로 명확하게 표시된 별개의 선택이에요. 변경 내용을 올리는 백업은 자동 백업이든 ‘지금 백업’이든 매번 별도의 암호화 파일로 저장돼요. 이전 파일은 앱의 ‘저장된 백업’ 목록에서 삭제하거나 Google 계정에서 이 앱의 데이터를 삭제할 때까지 남아 있고, Google 저장 공간을 차지해요.

5. 무료 버전의 광고

이 항목은 무료로 내려받고 선택 사항인 Plus 구독을 제공하는 DoseWeek 버전에 적용돼요. 무료 사용자에게는 광고가 보이고, Plus 구독자에게는 보이지 않아요. 광고는 Google Mobile Ads SDK(AdMob)가 보여 주고, 광고 동의는 Google의 User Messaging Platform(UMP)이 처리해요. 둘 다 Google이 제공해요. Google Play가 Plus 여부를 확인하기 전에는 광고를 보여 주지 않아요. Plus가 확인되면 앱은 광고를 바로 없애고 광고 SDK를 시작하지 않아요. 다만 그 전에 이미 보낸 광고 요청을 되돌리지는 못해요.

DoseWeek는 개인 맞춤형이 아닌 광고만 요청해요. 앱에서 광고 ID 권한과, 광고 ID·기여 분석·주제에 관한 Android 광고 서비스 권한을 제거하고, 설치 리퍼러 서비스도 제거해요. 그래서 SDK에는 광고 ID가 모두 0으로 읽혀요. 모든 광고 요청에는 개인 맞춤형이 아닌 광고를 요청한다는 표시가 붙어요.

개인 맞춤형이 아닌 광고에도 정보 처리가 필요해요. SDK가 광고를 요청하고 보여 주고 측정할 때, Google은 IP 주소, 기기·앱 정보(기기 모델, 운영체제 버전, 앱 버전, 언어 등), 광고 상호작용 정보(노출, 탭 등), 진단 정보, SDK가 이 앱용으로 만드는 식별자, 그리고 앱 세트 ID(app set ID)를 받아요. 앱 세트 ID는 Google Play 서비스가 제공하고, 기기에서 같은 개발자의 앱들이 함께 써요. Google은 이 정보를 광고 게재, 같은 광고가 너무 자주 보이지 않게 하는 빈도 제한, 사기·악용 방지, 광고 측정에 써요. Google은 자체 약관과 개인정보처리방침에 따라 이 정보를 받는 수령인으로서, 사용자의 국가 밖에 있을 수 있는 자사 서버에서 처리하고 Google이 정한 기간 동안 보관해요. DoseWeek는 이 기간을 줄일 수 없어요. 이 정보는 광고를 요청하고 보여 주고 측정하는 동안 인터넷으로 기기 밖으로 전송돼요. 개발자는 광고 노출 수나 수익 같은 AdMob 집계 보고서만 볼 수 있어요.

유럽경제지역, 영국, 스위스, 미국 일부 주처럼 법에서 동의를 요구하는 곳에서는 광고를 요청하기 전에 Google의 동의 메시지가 먼저 나타나요. 광고는 SDK가 요청해도 된다고 알려 준 뒤에만 요청해요. 메시지가 필요한지 확인하려고 앱은 실행할 때 무료 사용자에 한해 Google 동의 서비스에 문의해요. 이 요청도 Google에 전달되고, 광고 요청과는 별개예요. 설정 > 광고 개인정보 선택에서 언제든 선택을 확인하거나 바꿀 수 있어요. 선택이 필요 없는 지역에서는 그 화면에서 그렇게 알려 줘요. DoseWeek가 광고가 있는 무료 앱이 됐다는 1회 안내는 변경을 알리는 내용일 뿐이고, 읽었다고 동의한 것은 아니에요. 동의를 거절했거나, 양식을 불러오지 못했거나, 동의 서비스를 쓸 수 없어서 광고 처리가 허용되지 않으면 DoseWeek는 광고를 보여 주지 않고, 무료 기능은 모두 그대로 쓸 수 있어요. DoseWeek Android는 여전히 18세 이상만 쓸 수 있어요. 나이 확인은 바뀌지 않았고, 광고 동의, 사용 분석, 국외 이전과는 별개예요.

DoseWeek는 건강 기록, 메모, 약물 이름, 용량, 날짜, 식사, 화면 이름을 광고 SDK에 넘기지 않아요. 광고 요청에는 키워드, 콘텐츠 링크, 맞춤 타기팅도 넣지 않아요. 앱의 광고 코드는 기록을 읽지 않아요. 다른 SDK와 마찬가지로 Google SDK도 앱 프로세스 안에서 동작해서, 기술적으로는 앱 자체와 같은 파일 접근 권한을 가져요. DoseWeek는 기록을 SDK에 주지 않지만 이 접근을 기술적으로 막을 수는 없어요. 그래서 이 경계는 Google SDK가 Google이 공개한 대로 동작하는지에 달려 있어요.

AdMob은 Firebase나 Google Analytics와 연결하지 않아요. 광고 동의와 사용 분석 동의(3항)는 서로 별개예요. 한쪽을 선택해도 다른 쪽을 허용하거나 철회하지 않아요. 분석 설정에서는 광고 저장, 광고 사용자 데이터, 광고 개인 맞춤이 계속 거부된 상태로 유지돼요. 광고를 신고하려면 광고의 AdChoices 아이콘을 누르거나, 설정의 광고 신고를 쓰세요. 광고 신고는 광고가 나온 시각과 화면을 담은 지원 이메일을 열어요. 건강 정보는 들어가지 않으니, 직접 추가하지도 마세요.

광고 정보는 사용자의 국가 밖으로 이전될 수 있어요. 이전에 관한 자세한 내용은 아래와 같아요.

Plus가 확인되면 앱은 광고를 요청하지 않고 동의 확인도 하지 않아요.

6. Plus 구독과 구매 확인

Plus는 월간 또는 연간으로 자동 갱신되는 선택 구독이고, Google Play 결제 시스템(Google Play Billing)으로 판매해요. 가격과 결제 주기는 구매 전에 앱과 Google Play에 표시돼요. 결제와 Google 계정은 Google Play가 자체 약관에 따라 처리하고, DoseWeek는 결제 정보를 받지 않아요.

앱은 개발자의 구매 확인 서버가 Google Play에 구매를 확인한 뒤 Plus를 켜요. 앱이 서버로 보내는 것은 앱 패키지 이름, 상품, Google Play가 발급한 구매 토큰뿐이고, 건강 기록이나 다른 앱 내용은 보내지 않아요. 서버는 Google Play에 구매의 현재 상태를 묻고, 새 구매를 승인 처리한 뒤 상태를 앱에 돌려줘요. 구독이 갱신, 취소, 만료, 환불되면 Google Play가 서버에 알려요. 다른 인터넷 연결과 마찬가지로 서버와 호스팅 업체는 기기의 IP 주소를 볼 수 있어요. 서버는 이 주소를 구매 기록에 저장하지 않아요.

서버는 구매 토큰의 단방향 해시와 함께 상품, 구독 상태, 만료나 유예 기간 같은 관련 시각, 알림 식별자만 저장해요. 건강 정보, 기기 식별자, 이름, 이메일 주소는 저장하지 않고, 원래 토큰을 로그에 남기지 않아요. 서버 위치와 운영자 정보는 이 버전을 출시하기 전에 여기에 공개해요. 서버가 이 기록을 얼마나 보관하는지도 이 버전을 출시하기 전에 여기에 공개해요.

Google Play나 서버에 연결할 수 없으면, 앱은 마지막으로 검증된 Plus 상태를 마지막 검증 후 최대 7일 동안 써요. 그 밖의 경우에는 확인이 끝날 때까지 광고를 보여 주지 않고 Plus 도구도 잠가 둬요. 대기 중인 구매는 Google Play에서 완료되기 전까지 Plus를 켜지 않아요.

앱은 마지막으로 검증된 구독 상태의 짧은 캐시, 광고 빈도 카운터, 마지막 Plus 안내 시각, 30분 광고 없는 시간 기록을 기기의 앱 설정에 보관해요. 이 정보는 건강 정보가 아니고, 암호화 백업에 들어가지 않아요. DoseWeek는 이 정보를 어디에도 보내지 않아요. Plus 도구 데이터(식사 템플릿, 진료 요약 설정, 오늘 화면 배치)는 Android 백업과 기기 이전에서 제외된 보호된 앱 전용 파일에 보관하고, 이 버전에서는 암호화 백업에 포함되지 않아요. 설정의 모든 데이터 삭제는 Plus 도구 데이터를 삭제하지만 광고 카운터와 구독 캐시는 남겨요. 그래서 기록을 삭제해도 광고 제한이 초기화되지 않고, 구독도 취소되지 않아요.

구독 취소와 요금제 변경은 Google Play의 결제 및 정기 결제 > 정기 결제에서 할 수 있고, DoseWeek 설정에서 바로 열 수 있어요. 설정의 구매 복원은 같은 Google 계정으로 구매한 구독을 Google Play에서 확인해요. 앱은 시작할 때와 다시 돌아올 때도 확인해요. 앱을 제거해도 구독은 취소되지 않아요. 유료 앱이던 시절에 DoseWeek를 구매했다고 Plus 구독이 생기지는 않아요. 앱은 Plus나 광고를 정하려고 그 구매 내역이나 설치 날짜를 읽지 않아요.

7. 보관 기간과 삭제

기록은 사용자가 삭제할 때까지 그 기기의 앱 전용 저장소에 남아요. 설정의 모든 데이터 삭제를 쓰거나 앱을 제거하면 Android가 DoseWeek의 로컬 앱 데이터를 삭제해요. 개발자 서버에는 사본이 없어요.

앱 밖에 저장한 백업 파일과 CSV 내보내기 파일은 앱 데이터를 삭제하거나 앱을 제거해도 자동으로 삭제되지 않아요. 필요하면 Android 파일 앱이나 그 문서 제공자에서 따로 삭제해야 해요.

Google Drive 백업을 썼다면 앱 안의 백업 목록에서, 또는 Google 계정에서 이 앱의 데이터를 삭제해 클라우드 사본을 지워요. DoseWeek를 제거해도 그 사본은 삭제되지 않아요.

기기의 로컬 앱 데이터와 Drive 백업은 각각 따로 삭제할 수 있어요. 다른 제공자에 저장한 백업과 내보내기는 그 제공자의 관리를 따라요. DoseWeek를 제거하거나 Drive 연결을 해제해도, 그것만으로 Drive 백업이나 Google 식품 라벨 SDK 진단·사용 측정항목의 삭제를 요청하지는 않아요. 그 측정항목의 Google 처리와 보존은 Google 약관을 따라요. DoseWeek는 이를 직접 삭제할 수 없고, Google의 보존 기간도 알 수 없어요.

두 선택 동의 중 하나라도 거절하면 분석은 꺼진 채로 있고, 핵심 기능은 계속 쓸 수 있어요. 설정에서 어느 동의든 철회할 수 있어요. 철회하면 이후 분석 수집은 멈추지만, 이미 Google에 보낸 기록이 자동으로 삭제되지는 않아요.

분석 동의를 철회하면 이후 수집을 멈추고, 이미 초기화된 SDK에는 기기 내 분석 데이터와 식별자를 초기화하도록 요청해요. SDK를 초기화하지 않은 상태에서 데이터 삭제를 복구하는 경우에는, 나중에 사용자가 분석과 국외 이전에 다시 동의해 SDK를 켤 때 로컬 초기화를 먼저 요청해요. 이 동작은 Google 서버 기록이 삭제됐거나 디스크 정리가 끝났다는 확인이 아니에요.

분석이 켜져 있는 동안에는 앱에서 분석 데이터 삭제 요청 코드를 볼 수 있어요. 설정 > 사용 분석(선택)에서 “분석 데이터 삭제 요청 코드”를 열고 “삭제 요청 코드 보기”를 누르세요. 넓은 화면 등에서 설정이 섹션 목록으로 보이면 먼저 “데이터 관리”를 고르세요. 이 코드에는 현재 설치의 분석 기록을 찾기 위한 앱 인스턴스 식별자가 들어 있어요. 원하면 분석을 끄거나 앱 데이터를 삭제하기 전에 코드를 복사해 wonyoung@wonyoungchoi.dev로 삭제를 요청할 수 있어요. 코드를 보거나 복사하는 것만으로는 삭제 요청이 전송되지 않아요. 건강 기록은 보내지 마세요.

이 코드는 분석이 켜져 있는 동안에만 볼 수 있어요. 분석을 끄거나 앱 데이터를 삭제하면 그 코드는 다시 보여 주거나 복구할 수 없어요. 이전 식별자가 없으면 이미 전송된 그 설치의 기록을 찾지 못할 수 있어요. 분석 동의는 언제든 철회할 수 있어요.

8. 보안

DoseWeek는 Android 앱 전용 저장소를 쓰고, 시스템 백업과 기기 이전에서 데이터를 제외해요. Google Drive 백업을 켜지 않으면 자체 네트워크 연결로 건강 기록을 보내지 않아요. 켠 경우에도 올라가는 것은 4항에서 설명한 암호화된 봉투뿐이에요. 사용자가 만든 백업은 AES-256-GCM 인증 암호화를 쓰지만, 안전성은 백업 파일과 별도 복구 코드를 잘 보관하는 데에도 달려 있어요. 기기 잠금과 Android 보안 업데이트를 유지하고, 기기를 다른 사람에게 넘기기 전에 앱 데이터를 삭제하세요.

선택 사항인 앱 잠금은 Android 시스템 프롬프트로 기기 자체의 화면 잠금이나 생체 인식을 사용해요. DoseWeek는 생체 정보를 저장하지 않고, 잠금이 켜져 있는 동안 앱 전환 화면에서 내용을 숨겨요. 선택 사항인 알림은 기기 안에서만 예약돼요. 기본 문구는 치료 내용을 드러내지 않아요. 약 이름은 사용자가 켠 경우에만 보이고, 용량은 어떤 경우에도 보이지 않아요. 알림을 눌러도 앱이 열리기만 해요.

홈 화면 위젯은 일정 날짜, 상태, 일수를 보여 줘요. 잠금 해제된 홈 화면을 볼 수 있는 다른 사람에게도 이 정보가 보일 수 있어요. 앱 잠금을 켜면 위젯이 일정을 숨겨요. 약물 이름은 알림 세부 정보 표시와 약물 이름 표시를 모두 켠 경우에만 보이고, 용량은 보이지 않아요. 위젯은 읽기 전용이에요. 누르면 앱이 열릴 뿐 투여 기록은 저장되지 않아요. 위젯 처리는 기기 안에서 이뤄지고, 따로 네트워크로 보내지 않아요.

클라우드 백업을 켜면 이 기기에 저장되는 복구 코드 사본은 Android 하드웨어 키스토어에 있는 내보낼 수 없는 키로 봉인돼요. 통신은 Google API 호스트로 가는 TLS 연결로만 이뤄져요.

9. 방침 변경과 문의

Android 앱의 데이터 처리 방식이 바뀌면 이 원문과 공개 개인정보처리방침의 내용과 시행일을 함께 업데이트해요. 문의: wonyoung@wonyoungchoi.dev

10. DoseWeek 1.0.0 (versionCode 12)에 추가된 기능

이 항목은 Android용 DoseWeek 1.0.0 (versionCode 12)에 추가된 기능이 데이터를 어떻게 다루는지 설명해요. 3항과 4항의 캘린더 연동과 백업 설명도 같은 버전을 기준으로 해요. 시행일: 2026년 9월 23일.

식사 기록: 사용자가 직접 입력한 식사 이름, 날짜, 선택 시각과 식사 구분, 아는 범위에서 입력한 열량·단백질·탄수화물·지방 총량을 앱 전용 저장소에 저장해요. 비워 둔 값은 '모름'으로 남고 계산하지 않아요. 식사 기록은 암호화 백업에 포함돼요. 사용자가 요청할 때만 별도의 평문 CSV 파일로 내보낼 수 있고, 진료 요약에는 들어가지 않아요. 개발자는 식사 정보를 받지 않아요.

일정과 신체 그래프: 반복 간격 대신 직접 고른 주사 날짜 목록을 저장할 수 있어요. 체중 주간 변화와 BMI 그래프에는 공개된 일반 기준이나 사용자가 정한 개인 목표를 표시할 수 있어요. 고른 기준과 목표 값은 기기에 저장되고 암호화 백업에 포함돼요. 기준은 일반 인구 정보이고, 치료에 대한 조언이 아니에요.

백업 형식: 새 기능 때문에 암호화 백업 파일의 형식 번호가 올라가요. 이전 버전에서 만든 백업은 계속 복원할 수 있지만, 새 버전이 만든 백업은 이전 버전에서 복원할 수 없어요. 캘린더 일정 연결 정보와 저장하지 않은 임시 초안은 백업에 들어가지 않아요. 예상 기준 약물 선택도 백업에 들어가지 않으니 복원한 뒤 다시 골라야 해요.

음식 데이터 표: 이 버전에는 공개 데이터로 만든 읽기 전용 오프라인 음식 표(USDA FoodData Central: 퍼블릭 도메인 CC0 1.0, 출처 표기 요청, UK CoFID: Open Government Licence v3.0 근거, 일본 MEXT 일본식품표준성분표: MEXT 데이터 이용 안내와 사이트 약관, 한국 식품의약품안전처 자료: data.go.kr의 이용허락범위 제한 없음 조건)가 들어 있어요. 음식 검색은 기기 안에서만 이뤄져요. 입력한 검색어와 결과는 어디에도 보내지 않고, 표를 네트워크로 내려받거나 업데이트하지 않아요. 고른 시장·검색 언어 설정과 표에서 즐겨찾기로 저장한 음식은 기기에 저장되고 암호화 백업에 포함돼요. 값은 출처가 발표한 그대로 보여 주는 일반 참고 정보예요. 앱 안에서 각 출처, 라이선스, 출처 표기를 확인할 수 있어요. DoseWeek가 이 자료를 고르고 변환했어요. 어느 제공 기관도 이 가공물을 작성·검토·보증하지 않았어요. 출처 표기: U.S. Department of Agriculture, Agricultural Research Service. 선택 음성 입력: 사용자가 직접 시작하고, 설명에 동의하고, 마이크 권한을 허용한 경우에만 지원되는 기기와 언어에서 Android 기기 내 음성 인식을 써요. 로컬 인식을 쓸 수 없으면 직접 입력하면 돼요. 클라우드 음성 인식으로 바꾸지 않아요. DoseWeek는 오디오를 저장하지 않아요. 검토 패널에서 고칠 수 있는 전사문은 임시로만 있고, 백업과 로그에 들어가지 않아요. 화면을 나가거나 앱을 잠그거나 백그라운드로 보내면 지워져요. 임상 항목을 자동으로 채우거나 저장하지 않으니, 사실은 직접 기록 양식에 입력하고 확인해야 해요. 키보드 받아쓰기는 처리 방식이 다를 수 있는 별도 시스템 기능이에요. DoseWeek는 받아쓰기가 항상 로컬로 처리된다고 보장하지 않아요.

선택 식품 라벨 인식: 따로 설명을 보고 동의한 뒤, 사용자가 고른 사진에만 앱에 포함된 Google ML Kit 문자·바코드 인식을 써요. 사진 내용과 인식 결과는 기기에서 처리하고, ML Kit가 Google에 보내지 않아요. 다만 SDK는 설치 식별자, 기기·하드웨어 정보, 앱 정보, 처리 지연시간, 이미지 형식·해상도 같은 API 설정, 입력·출력 크기, 기능 버전, 이벤트 유형과 오류 코드 같은 진단·사용 데이터를 HTTPS로 Google에 보내요. SDK 유지관리 통신과 대기 중인 진단정보 전송은 검토 패널을 닫은 뒤에도 이뤄질 수 있어요. 이 예외는 식품 라벨 인식에만 적용되고, 다른 AI 기능이나 개발자 분석으로 넓어지지 않아요. 동의하지 않아도 직접 입력은 쓸 수 있어요. 앱을 설치하거나 여는 것만으로 인식이 시작되지는 않아요.

의료 관련 고지

DoseWeek는 개인 기록 도구이고, 의료기기가 아니에요. 질환을 진단, 치료, 치유, 예방하지 않고, 의학적 조언이나 용량·투여 시점 결정도 제공하지 않아요. 의약품과 치료에 관한 결정은 제품의 처방 정보와 자격을 갖춘 의료 전문가의 안내를 따르세요. 응급 상황이라고 생각되면 바로 지역 응급 서비스에 연락하세요.
